# ІгроЗвіт - локальний генератор баг-репортів для ігор

Застосунок перетворює довільний опис бага на український звіт із дев’ятьма полями. Працює з Qwen3-4B Q4_K_M у llama.cpp через OpenAI-сумісний API. Є індикатор очікування, повідомлення про помилки, копіювання та експорт у JSON/Markdown. Описи не записуються на диск сервером.

## Встановлення й запуск

Потрібні Windows x64, Python **3.11+**, відеокарта з підтримкою Vulkan і приблизно 6 ГБ вільного дискового простору. Для зафіксованих вимірювань використано RTX 4050 Laptop 6 ГБ. Застосунок та інструменти вимірювання не потребують pip-пакетів. Інтернет потрібен лише для завантаження рантайму й ваг.

Виконуйте команди **з кореня проєкту**, де лежить `local_models_task.md`:

```powershell
python lab4/tools/prepare_runtime.py
python lab4/app/run.py
```

Перша команда завантажить офіційний llama.cpp Vulkan і ваги Qwen3-4B Q4_K_M у `.runtime/`, перевірить SHA-256. Версії й контрольні суми зафіксовано в самому `prepare_runtime.py`. Друга команда запустить модель і вебсервер. Відкрийте **http://127.0.0.1:8000**. Завершення: **Ctrl+C** у консолі запуску.

Завантаження ваг займає близько 2,50 ГБ. Архів рантайму - близько 38 МБ. Модель і бінарні файли не потрібно додавати до Git.

Якщо рантайм уже працює, запускайте лише інтерфейс:

```powershell
python lab4/app/server.py
```

Для іншого локального OpenAI-сумісного сервера:

```powershell
$env:LOCAL_MODEL_BASE_URL = 'http://127.0.0.1:1234/v1'
$env:LOCAL_MODEL_NAME = 'ідентифікатор-моделі-з-v1-models'
python lab4/app/server.py
```

Сервер має підтримувати `response_format: json_schema` та chat completions. Для іншого рантайму окремо встановіть контекст щонайменше 4096 токенів і вимкніть міркування для Qwen3. Для Ollama/LM Studio параметри сумісності можуть відрізнятися; зафіксовані експерименти виконано в llama.cpp.

## Використання

1. Введіть один дефект або виберіть приклад.
2. Натисніть «Згенерувати баг-репорт» і дочекайтеся результату.
3. Перевірте факти, шкали та кроки відтворення.
4. Скопіюйте текст або збережіть JSON/Markdown.

Приклад: «Після завантаження збереження персонаж іноді застрягає в текстурах, неможливо рухатися, допомагає лише перезавантаження».

| Поле JSON | Поле інтерфейсу | Вміст |
|---|---|---|
| `title` | Назва звіту | Конкретний короткий заголовок |
| `description` | Опис | Симптоми, частота й обхідний шлях |
| `priority` | Пріоритет | Ціле **0-4**, 0 - невідкладний, 4 - мінімальний |
| `severity` | Серйозність | Ціле **1-4**, 1 - критична, 4 - косметична |
| `area_path` | Шлях області | Один шлях із закритого переліку областей гри |
| `repro_steps` | Кроки відтворення | Від 1 до 8 послідовних дій |
| `actual_result` | Фактичний результат | Що сталося |
| `expected_result` | Очікуваний результат | Як має працювати гра |
| `suggested_fix` | Рекомендація щодо виправлення | Що перевірити або змінити |

Ключі JSON англійські для інтеграції з трекерами, текстові значення й інтерфейс українські. Фактичну причину дефекту за одним описом визначити неможливо, тому рекомендація формулюється як дія для перевірки. Для нечіткого опису модель просить уточнення; оцінки 4/4 тимчасові до уточнення.

## Параметри генерації

| Параметр | Значення | Обґрунтування |
|---|---:|---|
| `temperature` | 0,2 | Менша варіативність формулювань для QA-звіту |
| `top_p` | 0,8 | Обмеження малоймовірних продовжень |
| `seed` | 1 | Контроль випадковості під час повторних перевірок |
| `max_tokens` | 1200 | Достатньо для дев’яти стислих полів; обмежує повтори |
| Контекст одного слота | 4096 | Системні правила, три приклади, опис і відповідь |
| Контекст сервера | 8192, 2 слоти | По 4096 токенів на одночасний запит |
| Режим міркування | вимкнено | Потрібне перетворення опису на структуру |
| Таймаут | 180 с | Контрольоване завершення при перевантаженні |

Використано системний промпт, три few-shot приклади, JSON Schema та серверну перевірку точного набору полів, типів, діапазонів і довжин. Модель оцінює пріоритет і серйозність окремо. Сервер не підміняє її відповідь шаблонним звітом і не виправляє оцінки приховано.

Введення обмежено 2400 символами; надто великий для контексту запит рантайм відхилить із повідомленням про скорочення опису. Історія попередніх користувацьких звітів у запит не передається. Фронтенд вставляє дані через `textContent`, тому HTML з опису не виконується.

## Якщо виникла помилка

| Повідомлення | Що зробити |
|---|---|
| Немає з’єднання з моделлю | Перевірити, що рантайм працює на 8080 і `/health` повертає `ok` |
| Модель не знайдено | Звірити `LOCAL_MODEL_NAME` з `/v1/models` |
| Час очікування вичерпано | Скоротити опис, закрити зайві запити або перевірити навантаження GPU |
| Рантайм відхилив параметри | Перевірити JSON Schema, режим міркування та розмір контексту |
| Некоректний JSON / неповний звіт | Уточнити опис і повторити генерацію |
| Перевищено ліміт токенів | Залишити один дефект і скоротити опис |
| Порт зайнятий | Завершити попередній запуск; не запускати два рантайми на 8080 |

## Файли

`core.py` - правила генерації, схема та клієнт моделі; `server.py` - локальний HTTP-сервер; `web/` - інтерфейс; `run.py` - запуск обох процесів; `tests/` - перевірки. Матеріали демонстрації містяться в `../demo/` та дублюються в `demo/` відповідно до тексту пункту 1.7.
